# Stability

Thermodynamic stability screening for SSE candidates: does the candidate
exist as a compound, over what voltage range is it stable against a Li
reservoir, and does it react violently with the electrodes it will actually
touch?

---

## How it works (plain-language summary)

All three calculations are built on the same idea: **grand-canonical phase
diagrams**. A normal (closed-system) phase diagram asks "given these atoms,
what's the lowest-energy way to arrange them into phases?" A grand-canonical
phase diagram instead fixes the *chemical potential* of one species (here,
Li) and lets the system trade that species with an external reservoir --
which is exactly what happens at an electrode interface, where Li ions flow
in and out as the cell charges and discharges.

### Shared Step 0 -- one relaxed energy, reused everywhere

All three calcs need the candidate's energy on the same footing as the
Materials Project reference phases they're compared against. `candidate_to_entry()`
relaxes the candidate once with an MLIP (cell + positions, two-stage) and
wraps the result in a `ComputedStructureEntry` -- this single entry feeds
Calc 1, 2 and 3. Don't re-relax per calculation.

### Calc 1 -- `existence_check()`: does this compound exist?

Closed system, no reservoir. Build a `PhaseDiagram` from the candidate +
every competing phase in its chemical system (pulled from Materials
Project), and ask how far above the convex hull the candidate sits
(`e_above_hull`, eV/atom). `e_above_hull == 0` means the candidate *is* the
most stable arrangement of those atoms; a positive value means it wants to
decompose into the phases listed in `decomposes_into`.

This is the cheap **hard gate**: most random structures generated by a GA
simply aren't real compounds, and there's no point computing a voltage
window or an interface reaction for something that falls apart on its own.
`tol` (default 50 meV/atom) sets how much metastability is tolerated --
see [Sun et al. 2016](#citations) for why 50 meV/atom is a defensible cut
(most synthesizable metastable phases fall within ~36 meV/atom of the hull).

### Calc 2 -- `electrochemical_window()`: the ESW

Open the system to a Li reservoir at chemical potential `mu_Li = mu_Li^0 - eV`
(referenced to Li metal, `mu_Li^0 = 0`; so `V = -mu_Li`). Sweep `mu_Li` from
0 down to `mu_min` (default -6 eV, i.e. V from 0 to 6), and at each point
build a `GrandPotentialPhaseDiagram` and ask whether the candidate
(`GrandPotPDEntry`) is still on the grand-potential hull.

The contiguous range of V where it's stable is the electrochemical stability
window. Outside that range, the result also reports what the candidate
decomposes *into* at the reduction (low-V) and oxidation (high-V) edges
(`reduction_products` / `oxidation_products`).

**This is reported as a SOFT penalty, not a pass/fail gate** -- see
[Caveats](#caveats-and-deviations-from-the-literal-guide-recipe) for why.

### Calc 3 -- `interfacial_reactivity()`: does it react with the electrode?

Two-phase reaction energy between the candidate and a specific electrode
composition (Li metal anode, or a cathode material) at a given Li chemical
potential. Sweeps the mixing ratio between the two phases and reports the
most negative reaction energy found (`min_reaction_energy_ev_atom`) -- large
negative numbers mean an aggressive interfacial decomposition.

Also a **soft penalty**.

## Energy-scale consistency (Section 0)

All three calcs compare the candidate's MLIP energy directly against
Materials Project entries, which carry **MP2020 compatibility corrections**
(anion corrections, GGA/GGA+U mixing shifts -- real offsets of tens to
hundreds of meV/atom). If the candidate's energy isn't on the same scale,
hull distances come out wrong with **no error raised**.

| MLIP | MP2020-corrected scale? | Usable here? |
|------|--------------------------|---------------|
| CHGNet | yes (trained on corrected MP energies) | yes |
| M3GNet (matgl) | yes | yes |
| MACE-MP-0 | **no** (trained on uncorrected energies) | not without a manual correction (not implemented) |
| SevenNet | **no** | not without a manual correction (not implemented) |

`load_calculator(model="auto")` therefore only tries CHGNet then M3GNet.
Passing `model="mace"` or `model="sevennet"` raises immediately with an
explanation rather than silently producing wrong-but-plausible hull
distances. `mp_api`'s `get_entries_in_chemsys(..., additional_criteria=
{"thermo_types": ["GGA_GGA+U"]})` already applies MP2020 corrections, so no
manual `MaterialsProject2020Compatibility` step is needed.

This pragmatic strategy introduces ~20-40 meV/atom of cross-method noise
(MLIP vs. DFT). `DEFAULT_TOL_EV_ATOM = 0.050` is chosen with that noise floor
in mind -- don't tighten it without accounting for it. A fully
self-consistent alternative (relax every competitor with the same MLIP too)
would remove this noise at the cost of N extra relaxations per chemsys; not
implemented here.

## Usage

### CLI

```bash
# Everything, on a CIF file
python stability.py --cif candidate.cif --all

# Just the hard existence gate
python stability.py --cif candidate.cif --existence --tol 0.05

# Electrochemical window
python stability.py --cif candidate.cif --esw

# Interfacial reactivity vs. Li metal anode
python stability.py --cif candidate.cif --interfacial --electrode Li

# Interfacial reactivity vs. a cathode material at V=4 (mu_Li=-4)
python stability.py --cif candidate.cif --interfacial --electrode LiCoO2 --mu-li -4.0

# From a Materials Project entry instead of a CIF
python stability.py --mp-id mp-1234 --all

# Phase-5-style plumbing sanity check (no MLIP needed)
python stability.py --validate
```

### Python API

```python
from stability import StabilityScreen, screen_population, acquire_structure

screen = StabilityScreen(model="auto", tol=0.050)   # loads CHGNet/M3GNet once

structure = acquire_structure(cif_path="candidate.cif")
result = screen.screen("candidate_001", structure,
                        electrodes=[("Li", 0.0), ("LiCoO2", -4.0)])
print(result.summary())
```

### GA-facing population screen

```python
from stability import StabilityScreen, screen_population

screen = StabilityScreen(model="auto")
candidates = [(rec["id"], rec["structure"]) for rec in population]
records = screen_population(screen, candidates)

survivors = [r for r in records if r["passes_existence"]]
# Each survivor also carries:
#   r["anode_penalty_ev_atom"]      -> soft penalty at V=0 (Li metal anode)
#   r["cathode_penalty_ev_atom"]    -> soft penalty at V=4 (typical cathode)
#   r["interfacial_li_ev_atom"]     -> reaction energy vs. Li metal anode
```

`screen_population()` mirrors the bandgap module's `screen_population()`
pattern: it annotates each record in place and prints a one-line gate
summary. Unlike the bandgap gate, `passes_existence` is the only hard
pass/fail field -- the `*_penalty_ev_atom` / `*_ev_atom` fields are
continuous values meant to be folded into the GA's fitness function as
penalties, not used to drop candidates outright.

`StabilityScreen` caches MP competitor entries per chemsys
(`_competitor_cache`), so candidates sharing a chemical system (the common
case within one GA generation) only trigger one `get_entries_in_chemsys`
call.

## GA integration

```
1. relax (candidate_to_entry)         -> kill if not converged
2. Gate A (HARD): existence_check     -> kill if e_above_hull > tol (default 50 meV/atom)
3. Gate B: bandgap / bulk modulus     -> handled by other modules
4. ionic conductivity                 -> the optimization objective (other module)
5. ESW + interfacial reactivity       -> SOFT penalties on fitness, ranked by
                                          decomposition-energy magnitude at the
                                          operating voltages (anode ~0V, cathode ~4V)
```

Step 5 deliberately does **not** gate on the ESW window -- see below.

## Validation

`validate()` (no MLIP required) fetches each material's *own* MP entry for a
handful of known-stable SSEs and runs `existence_check` against its own
chemsys's competitors. Because the entry IS one of the competitors, it must
land at `e_above_hull == 0` by construction -- this checks chemsys
completeness, `thermo_types` filtering and MP connectivity, independent of
any MLIP:

| MP ID | Material |
|-------|----------|
| mp-942733 | Li7La3Zr2O12 (LLZO) |
| mp-696128 | Li10GeP2S12 (LGPS) |
| mp-1185319 | Li6PS5Cl (argyrodite) |
| mp-22905 | LiCl |
| mp-1153 | Li2S |

```bash
python stability.py --validate
```

## Caveats and deviations from the literal guide recipe

### 1. ESW is a soft penalty, never a hard gate

[Zhu, He & Mo (2015)](#citations) showed that several real, working SSEs
(notably **LGPS**) have a computed ESW that does *not* cover typical
operating voltages -- they survive in practice via **kinetic
passivation**: a thin decomposition layer forms at the interface and then
stops further reaction. A hard ESW gate would delete LGPS-class materials
from the population. Instead, `electrochemical_window()` always reports
`anode_penalty_ev_atom` / `cathode_penalty_ev_atom` (the grand-potential
`e_above_hull` at V=0 / V=4, regardless of whether the candidate is inside
its own stability window) -- feed these into the fitness function as a
continuous penalty, ranked by magnitude.

### 2. Pure-Li-electrode interfacial reactivity needs a different code path

The literal recipe for Calc 3 is `GrandPotentialInterfacialReactivity(c1=candidate,
c2=Composition("Li"), grand_pd=..., pd_non_grand=pd, norm=True,
include_no_mixing_energy=True)`. For a **pure Li metal anode**
(`electrode_comp="Li"`), this raises `ZeroDivisionError` inside pymatgen:
the grand-potential machinery strips chempot elements (Li) from both `c1`
and `c2` before normalizing, and `c2=Composition("Li")` becomes a
zero-atom composition.

Conceptually this makes sense -- Li metal *is* the mu_Li=0 reservoir, so
wrapping it in another grand-potential reservoir abstraction is degenerate.
`interfacial_reactivity()` therefore special-cases electrodes whose
composition consists entirely of the chempot element(s): it falls back to
the plain `InterfacialReactivity(c1=entry.composition, c2=electrode_composition,
pd=PhaseDiagram(all_entries), norm=True, use_hull_energy=True)`, which
works correctly. Non-pure electrodes (any real cathode material) use
`GrandPotentialInterfacialReactivity` exactly as the guide describes. Any
`mu_li != 0` passed alongside a pure-Li electrode is ignored (with a
warning) since Li metal defines `mu_Li = 0` directly.

### 3. No symmetry analysis (spglib-free by design)

Unlike `bulk_modulus/physics_bulk_modulus.py`, this module never imports
`pymatgen.symmetry` (no `SpacegroupAnalyzer`, no primitive-cell reduction).
GA candidates are already ordered, primitive-enough structures, and none of
the three calcs need symmetry information -- avoiding the import keeps this
module usable in environments where spglib's compiled extension is broken
(a real issue encountered during development on this machine). Disordered
structures (e.g. raw LLZO straight from MP) are rejected with a pointer to
`bulk_modulus.physics_bulk_modulus.order_structure()` rather than
re-implementing Ewald ordering here.

### 4. `thermo_types` is pinned to GGA/GGA+U

`get_entries_in_chemsys(..., additional_criteria={"thermo_types":
["GGA_GGA+U"]})` excludes r2SCAN entries. Mixing r2SCAN reference energies
with CHGNet/M3GNet (GGA/GGA+U-trained) candidate energies would reintroduce
the Section-0 energy-scale problem from the other direction.
